# Swarm Test Field

**Completed.** Swarm Test Field takes no submissions, is not scored and pays nothing: Swarm Test Field v2 took its place. It carried 5% of subnet emissions until then. This page describes the family as it ran, for reference, and its champions stay published in the [champions repository](https://github.com/swarm-subnet/swarm-champions). The live family is [Swarm Test Field v2](../test_field_v2.md); see [all completed families](README.md).

Fly the company's real drone test field from its dock: take off, count the people on the field, report where each one is, and land back in the dock without ever coming within 1 m of the field's edge.

---

A DJI Matrice 4TD sits in its DJI Dock 3 on the test field in Santa Coloma, Andorra. Your model presses take-off, and the dock opens and lifts the drone to 9.5 m. From there your model flies: it looks over the field with a colour camera, a thermal camera and two zoom lenses, and reports each person it finds with a box on the image it saw them in and the spot where they stand. Then it presses return home, and the dock flies the drone back and lands it. The field has no fence: its edge is an invisible line, and the drone must stay more than 1 m inside it from take-off to landing. It never flies higher than 10 m above the dock, so the tree crowns that hang over the field are solid obstacles.

The drone, the dock, the controls, the cameras, the sensor errors and the link delay are the same as in [Swarm Sentinel](../solar_patrol.md). The field is a real place, and every rule here can be flown on it with the real drone.

Every array arrives as read-only float32: copy it before changing it in place. Each `act()` call gets all five keys, in the same shapes as Sentinel's.

- **`rgb` / `thermal`**: the main camera, colour or thermal, whichever your last action picked. Only the picked feed is drawn; the other one is all zeros. A new frame is taken every 0.5 s, so five decisions in a row see the same image; `frame_age_s` in the state says how old it is.
- **`zoom`**: the last close-up you asked for, all zeros before the first one.
- **`state`**: 31 values, every decision. See [State vector layout](#state-vector-layout).
- **`site_map`**: the field's edge, the tree crowns and the houses around it, sent **on the first observation of a patrol only** and all zeros after it. Keep it. See [Site map layout](#site-map-layout).

Your program stays alive for the whole patrol and is reset between seeds, so it can keep its own memory.

## State vector layout

The layout is [Sentinel's](../solar_patrol.md#state-vector-layout), index for index. Positions count from the dock: the dock is always at 0, 0, 0, wherever the seed stands it. Axes are east, north and up, in metres. Every height in the state is measured **above the dock**; the scoring rules measure height **above the ground straight under the drone**, and the field slopes about 9 % down to the east and 6 % down to the south, so the two differ.

Two values mean something of their own here:

| Index | Field | Meaning on the field |
|---|---|---|
| 21 | `flight_limit_distance_m` | Distance to the field's edge, m, never negative |
| 22 | `inside_flight_limit` | 1 inside the field's edge, 0 outside |

`time_left_s` (index 9) counts down from 180. There is no night: `night_mode` changes nothing.

## Site map layout

The layout is [Sentinel's](../solar_patrol.md#site-map-layout), in metres from this seed's dock.

| Index | Field | Meaning |
|---|---|---|
| 0 | `fence_count` | Number of corners of the field's edge |
| 1–128 | `fence_xy` | The field's edge as (east, north) pairs, in order around it; unused slots are 0 |
| 129 | `limit_count` | The same count |
| 130–257 | `limit_xy` | The same edge: on the field the fence and the flight limit are one line |
| 258 | `table_count` | Number of tree crowns: the field has no panel tables, so these rows carry the crowns |
| 259–578 | `tables` | Up to 64 crowns, nearest the dock first, 5 numbers each: centre east, centre north, the crown circle's diameter, the same diameter again, and 0; unused slots are 0 |
| 579 | `building_count` | Number of houses listed around the field, up to 16 |
| 580–659 | `buildings` | Up to 16 houses, nearest the dock first: centre east, centre north, length, width, heading of the long side in degrees; unused slots are 0 |

The edge is the surveyed boundary of the real field: 46 corners around 2,755 m².

**From the dock to latitude and longitude.** The map's frame is flat east and north around the survey's origin, `site.origin_lat_lon` (lat0, lon0) in the map's manifest. With (e, n) a point in that frame in metres, and the dock's own place in it found by subtracting any corner of `fence_xy` from the same corner of the surveyed edge:

```text
lat = lat0 + n / 111319.49        lon = lon0 + e / (111319.49 · cos(lat0))
```

On the real field, use the dock's own latitude and longitude in place of the origin, and a report's east and north directly as e and n.

## Actions

One `act()` returns **26 values**. The first 24 are [Sentinel's](../solar_patrol.md#actions), in the same order with the same meaning; two follow them:

| # | Value | What it does |
|---|---|---|
| 0–23 | Sentinel's actions | Sticks, gimbal, feeds, zoom, report class, image and box, take-off, return home, cancel |
| 24 | `report_east` | Where the reported person stands, east of the dock: a share of 100 m, in [-1, 1] |
| 25 | `report_north` | The same, north of the dock |

The two position values are read only when `report` is pressed, together with the class, the image and the box.

**Buttons count once.** `zoom`, `report`, `take_off`, `return_home` and `cancel_return` act only on the decision their value rises through 0.5. Holding one at 1.0 presses it once; to press again, send 0.5 or less for at least one decision first.

Values are clipped to their bounds. An action with any NaN or infinite value, or one that does not hold 26 values, becomes all zeros.

## The patrol

One episode is one patrol and one seed, with Sentinel's flight phases: the dock takes the drone up to 9.5 m above it, the model flies, and `return_home` hands it back to the dock to fly home and land. See [Sentinel's patrol](../solar_patrol.md#the-patrol) for how take-off, return home, landing and cancel work.

**The 10 m ceiling.** The drone never rises more than 10 m above the dock: like the real dock's height limit, its climb slows and stops there, whether your model, the dock's take-off or its return home is climbing. A climb held at full stick stops within about 0.15 m of the line. The take-off ends 9.5 m above the dock, half a metre under it. Return home follows Sentinel's three cases, except that a return pressed more than 50 m from the dock climbs to 9.5 m, not 20 m; nearer, it keeps its height. The ceiling counts from the dock, as on the real aircraft, not from the ground under the drone: the field rises and falls about 6 m from one end to the other, so over its low end the drone can be more than 10 m above the ground, and over its high end only a few metres above it. There, passing within 5 m of a person, measured in 3D to a 1.8 m tall person, is easy to do: keep your distance across the ground. The flight term's height half, full up to 22 m above the ground, can no longer be lost.

**Tree crowns are solid.** The simulator makes a tree's trunk solid and lets a drone fly through its crown; the real drone would hit it. So while the drone is out of the dock, its position across the ground inside any crown circle ends the patrol as a collision, at any height, and **the seed scores 0**. About 22 crowns hang over the field and cover about 10 % of it. The site map gives every crown circle (see [Site map layout](#site-map-layout)), and the crowns show in the images.

**The edge rule.** The field has no fence. While the drone is out of the dock (taking off, flying, returning or landing), if its position across the ground is outside the field's edge or 1.0 m or less inside it, the patrol ends on the spot as a `flight_limit` end, **the seed scores 0**, and the trip counts as a mistake under the [×5 rule](#across-the-epoch-the-5-rule). This holds for the dock's own flights too: a return home pressed where the straight line to the dock passes close to the edge ends the patrol on the way. State index 21 gives the distance to the edge every decision.

The patrol ends on the first of:

| End | When | What it keeps |
|---|---|---|
| Landed | The drone settles on the dock's pad after a return | Everything |
| Timeout | 180 s run out | Detection, coverage and height, not the landing |
| Collision | The drone hits anything, the dock included, flies into a tree crown's circle, or tips past its tilt limit | Nothing: the seed scores 0 |
| Flight limit | The drone comes within 1 m of the field's edge, or leaves it | Nothing: the seed scores 0, and the trip is a mistake under the ×5 rule |

The 180 s are planned as 15 s for take-off, 30 s to visit and report the people, 95 s to look over the field, and 40 s to come home and land; only the total is enforced. A return pressed too late ends as a timeout, without the landing.

## The field

- **One real field, the same in every seed**: the ploughed field, its walls and lane, the trees and houses around it and the valley out to the horizon, rebuilt from the company's own drone survey. Nothing on it moves.
- **The dock** stands on a different spot of the field each seed: at least 5 m inside the edge, clear of anything standing and of every tree crown by 3.4 m, on ground no steeper than 10°.
- **Day only**, with the sun set by the seed.
- **Wind** is none, light or strong, drawn per seed in Sentinel's daytime shares: about 5 %, 70 % and 25 %.
- **People**: 0 to 6 per seed, none in about 15 % of seeds. They wear everyday clothes and stay in one place the whole patrol, in one of three poses: standing, crouching or kneeling, or lying on the ground. Each stands at least 1.5 m inside the edge, 8 m from the dock, 3 m from everyone else, and never under a tree crown. Nobody reacts to the drone, and there are no animals or vehicles.

## Scoring

### Per seed

```text
seed = 0.70 · detection + 0.20 · coverage + 0.10 · flight
```

The terms are [Sentinel's](../solar_patrol.md#per-seed), with the people on the field as the threats:

- **Detection**, with people on the field: valid reports ÷ (people + false alarms). On an empty field it is the coverage ÷ (1 + false alarms).
- **Coverage**: the share of the field searched, in 2 m cells inside the field's edge and outside every crown circle (no camera above a crown sees the ground under it), seen from 20 m or lower above the ground under the camera, sharp enough that a person would be about 6 pixels across.
- **Flight**: half for landing in the dock after your own `return_home`, half for keeping the peak height above the ground at 22 m or lower, falling to 0 at 30 m; under the 10 m ceiling that half is always earned.

**A seed scores 0** when the drone never takes off, comes closer than 5 m to a person (measured in 3D to a 1.8 m tall person) while out of the dock, trips the edge rule, or collides with anything, a tree crown included. Touching the dock's landing pad is not a collision.

**A report is valid** when all of these hold:

1. Sentinel's checks pass: the frame was taken no higher than 24 m above the ground under the camera, the box covers a real person (intersection over union of at least 0.5 with the tight box around their visible pixels), the class is person, and it is the first valid report of that person.
2. The reported spot, `report_east` and `report_north` times 100 m from the dock, lies within **2.0 m** across the ground of where the person is. Where a person is means the centre of the box their body covers seen from above: between the feet of someone standing, the middle of the body of someone lying.

A report that fails is a false alarm; a wrong spot has its own verdict, `wrong_position`, and leaves the person to be reported again. The number of people your model counted is the number of its valid reports: there is no separate count.

### Across the epoch: the ×5 rule

After every seed is scored on its own, **each missed person, each false alarm and each edge trip turns 5 of the model's best seeds to 0**, and the score is the mean over all the seeds, the zeroed ones included. It never goes below 0. It is [Sentinel's rule](../solar_patrol.md#across-the-epoch-the-5-rule) with one more mistake: a patrol the edge rule ends scores 0 on its own seed and also counts once against the rest (`edge_trips` in the seed's results). A collision, a tree crown included, stays a 0 for its own seed only. A false alarm is any report that fails: a wrong box, a spot more than 2 m off, a person reported twice. A seed your model abandons, by failing on slow-act strikes or by its process exiting, scores 0 and counts every person on the field as missed, the ones it already reported included, from its very first decision.

Over 1,000 seeds, for a model whose seeds average 0.970 and whose best seeds score 1.00:

| Mistakes across the epoch | Seeds set to 0 | Score |
|---|---|---|
| None | 0 | 0.970 |
| One missed person | 5 | 0.965 |
| One missed person and one false alarm | 10 | 0.960 |
| One edge trip | 5, and the tripped seed scores 0 | about 0.964 |
| 200 or more | all 1,000 | 0 |

A model that never reports, or reports everything, ends at 0 on any epoch with people on the field.

## Local testing

Start from the starter agent. It flies a whole patrol from the state and the site map: it takes off, sweeps the field in lanes 9 m apart, at least 7 m inside the edge and 3.5 m off every crown circle, 9 m above the dock, returns home and lands. It never looks at the images and never reports, so it finds nobody, and since it does not know where anyone stands it can pass within 5 m of a person over the field's high end; replace its sweep with your own search. Run these from the repo root:

```bash
mkdir -p my_model
cp miner/src/submission_template/test_field_drone_agent.py my_model/drone_agent.py
swarm model test --source ./my_model --family-id cf_test_field
swarm model package --source ./my_model --family-id cf_test_field
swarm model verify --model Submission/submission.zip
swarm benchmark --model Submission/submission.zip --family-id cf_test_field --seeds-per-group 1 --workers 1
```

- The field's map ships in swarm-worlds; an install without it refuses the family by name.
- Every seed is first flown once by a scripted reference pilot that checks the seed can be done: everyone on the field reported, no false alarm, the edge kept and a landing in the dock. The verdict is cached, so a seed costs this check only the first time.
- To fly one exact seed, pass `--seed-file seeds.json` with `{"schema_version": "challenge_family_seed_file.v1", "family_id": "cf_test_field", "type_seeds": {"type9_testsite": [1002]}}`.
- On a 12-core server the starter's patrol, about 90 s of flight, takes about 65 s to run through the benchmark, and the reference check adds about 80 s of CPU the first time a seed is flown. A worker grows to about 2,950 MiB of memory: keep `--workers` low on a laptop.
- Each seed's line shows its missed people, false alarms and edge trips, and under the table the benchmark applies the ×5 rule to the seeds it flew: the plain mean beside the score after the rule. On a handful of seeds one mistake zeroes most of them; the leaderboard applies the same rule across the epoch's 1,000 seeds.
- Always pass `--family-id cf_test_field`: without it, `swarm benchmark` runs Swarm Sentinel.

To watch a patrol, film it with `swarm video` (it needs a video writer the install does not include), or look around the field with `swarm visualize`:

```bash
uv pip install opencv-python-headless
swarm video --model Submission/submission.zip --seed 1002 --type 9 --family-id cf_test_field --backend local
swarm visualize --type 9 --family-id cf_test_field --seed 1002
```
